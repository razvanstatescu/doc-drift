PAY-158 Remove the v1 refunds endpoint, fix version 2026.12

Context

v1 refunds only support full refunds, take amounts in a different field from the rest of the API, and have no idempotency. Support spends about 6 hours a month on refunds issued twice through v1. v2 refunds cover every v1 use case.

Decision

We retire POST /v1/refunds:

  1. Now: v1 answers with Deprecation and Sunset headers, and is only served when a feature flag is on.

  2. By 2026-11-30: every internal caller moves to POST /v2/refunds. Merchant success contacts the 9 merchants still on v1.

  3. Release 2026.12 (sunset 2026-12-15): the endpoint and its flag are deleted. Calls get 404.

Options considered

  • Keep v1 as a thin wrapper over v2. Rejected: the wrapper would still need its own tests and docs forever, and still could not offer idempotency without a client change.

  • Remove it at once. Rejected: 9 merchants need time to migrate.

Consequences

  • The Refunds API guide documents v1 only as a migration aid until the sunset.

  • After release 2026.12, a v1 call is a client bug, not an incident.

  • The removal ties into : after it, every money-moving endpoint is idempotent.
