Context

Charges used to call the PSP capture API inside the HTTP request. When the PSP slowed down, our request threads filled up, latency on POST /v2/charges went above 3 seconds, and checkout timed out. The PSP was slow; we made it look like we were down.

Decision

Capture moves out of the request path. The API writes a settlement_jobs row in the same transaction as the charge and answers 201. A separate worker deployment claims jobs and talks to the PSP.

The queue is a Postgres table, not a message broker. Workers claim rows with FOR UPDATE SKIP LOCKED, so many workers can run without coordination. The worker is src/workers/settlement-worker.ts.
