How to read this

Open payments-api next to this page and follow a charge from the HTTP request to settlement. It takes about an hour. You should have finished first.

1. Start-up: src/server.ts

The process reads its configuration with loadConfig() from src/config.ts, creates the Postgres pool with createPool() from src/db/pool.ts, and builds a Router. Routes are attached in one place:

typescript

The HTTP server itself lives at the bottom of server.ts: it reads the body, matches the route, calls the handler and writes JSON. If PAYMENTS_ROLE is worker, no server starts and the settlement worker runs instead.

2. Routing: src/routes/index.ts

registerRoutes() calls one registerX() function per area: charges, refunds and webhooks. To add an endpoint, add it to the area's file; to add an area, add a file and call it from registerRoutes(). The router in src/http/router.ts is deliberately tiny: exact segments and :params, nothing else.

3. A charge: src/routes/charges.ts

  1. The handler checks the Idempotency-Key header, then validates the body with validateChargeRequest().

  2. withIdempotency() from src/idempotency.ts returns the stored response if the key was seen in the last 24 hours. The reasoning is in .

  3. The charge row and a settlement_jobs row are inserted, and the API answers 201 without waiting for the PSP.

4. Settlement: src/workers/settlement-worker.ts

startSettlementWorker() runs a loop per slot that claims jobs with FOR UPDATE SKIP LOCKED. Read next to this file.

5. The PSP answers: src/routes/webhooks.ts

The charge.settled webhook closes the loop. Note how failures go to a dead-letter table instead of returning an error to the PSP.

Conventions

  • Money is always an integer in minor units, in SQL and in JSON. 12.50 EUR is 1250.

  • Handlers return { status, body }; they never touch the raw response.

  • Error bodies are { "error": "snake_case_code" }. Clients match on the code, so never reword one.

  • SQL lives next to the handler that uses it. There is no ORM.
