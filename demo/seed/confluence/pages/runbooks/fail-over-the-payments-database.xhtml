When to use this runbook

Patroni fails over on its own when the primary stops answering for 30 seconds. Use this runbook when it does not, or when you need a planned switchover (host maintenance, a stuck primary that still answers health checks).

A failover drops every open connection. Charges in flight return 500 and clients retry with the same Idempotency-Key, so no charge is created twice. Tell the incident channel before you start.

Connection budget

After a failover every pod reconnects at once. The new primary must accept all of them, so check the budget before and after any change to the pool size.

yamldeploy/helm/values.yaml (excerpt)

PAYMENTS_DB_POOL is the pool size per pod (see src/db/pool.ts). With 3 API pods and up to 8 worker pods that is 11 x 20 = 220 connections at the worst moment, against max_connections = 200 on payments-pg. Patroni reserves 20 for superuser and replication, so in practice the API reconnects first and some workers retry for up to 1 minute. This is expected. PgBouncer (PAY-151) will remove the problem.

Do not

  • Do not raise the pool size during an incident to "help" reconnects. It makes the connection storm worse.
