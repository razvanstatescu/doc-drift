PAY-175 Replay dead-lettered webhooks from the admin console

Last reviewed

2026-10-27

When to use this runbook

When a PSP webhook fails to process, payments-api still answers 200 (so the PSP stops retrying) and stores the event in webhook_dead_letters. Charges stay in settling until the event is replayed. Replay when:

  • The Webhook dead letters panel is above 0 for more than 15 minutes.

  • A merchant reports charges stuck in settling for more than 1 hour.

  • You have just fixed the cause of a processing error, such as a database outage.

A 401 signature_invalid is not a dead letter. It means the signing secret is wrong; see .

Steps

  1. See what would be replayed. Narrow it with --since to the start of the incident.

    bash

  2. Replay. The script posts each event to the internal endpoint POST /internal/webhooks/replay/:id, which applies it and deletes the dead letter. The default limit is 500 events per run.

    bash

  3. Run it again until it prints events: 0.

  4. Spot-check 3 replayed charges with GET /v2/charges/:id. They should be settled with a settled_at time.

Replay is safe to repeat

webhook_events has the PSP event id as its primary key, so a replayed event that was already applied is ignored. If a replay fails, the event stays in webhook_dead_letters and you can run the script again.
