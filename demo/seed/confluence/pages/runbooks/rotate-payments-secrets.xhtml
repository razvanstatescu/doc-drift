What this covers

payments-api reads 3 secrets from Vault through the payments-secrets ExternalSecret:

Secret flag

Env var in the pod

Rotate

psp-api-key

PSP_API_KEY

Every 90 days, or at once if leaked

webhook-signing-secret

WEBHOOK_SIGNING_SECRET

Every 90 days, together with the PSP dashboard

db-password

PAYMENTS_DB_PASSWORD

Every 180 days

Rotation restarts every payments pod. Do it outside the 18:00 to 22:00 CET peak, and never during an open incident unless the secret leaked.

Before you start

  • You need the payments-secrets-admin Vault policy. Check with vault token lookup.

  • Write the new value to a file with mode 600. Never paste secrets into a terminal history or the incident channel.

Rotate the PSP API key

  1. Create a second key in the PSP dashboard. Both keys stay valid until you revoke the old one.

  2. Store it in Vault and restart the pods:

    bash /tmp/psp-key.txt ./scripts/rotate-secrets.sh --secret psp-api-key --value-file /tmp/psp-key.txt shred -u /tmp/psp-key.txt]]>

  3. Create a test charge in staging and check for 201.

  4. Revoke the old key in the PSP dashboard 1 hour later.

Rotate the webhook signing secret

The PSP signs every webhook with this secret. The PSP dashboard lets you keep the old secret valid for 24 hours, so set that before you rotate.

Then watch for 401 signature_invalid responses on /webhooks/psp. A few during the restart are expected. If they continue for more than 5 minutes, see .

Rotate the database password

  1. Ask the database on-call to add the new password to the payments_app role (Postgres keeps 1 password per role, so this is a short window).

  2. Run the script with --secret db-password immediately after.

  3. Check the pool reconnects: no password authentication failed errors in the logs.
