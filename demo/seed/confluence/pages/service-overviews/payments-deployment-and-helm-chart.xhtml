How a release ships

  1. A merge to main builds the image and tags it with the version in package.json.

  2. The release pipeline bumps image.tag in deploy/helm/values.yaml and runs helm upgrade in staging.

  3. After 30 minutes of clean staging metrics, a person approves the production step. Production runs the same command against prod-eu-west-1.

Changing a value

Change deploy/helm/values.yaml in a pull request. Values changes ship like code: staging first, then production with an approval. Never run helm upgrade by hand with --set; the next release would silently undo it.
