What it does

The PSP tells us about charge outcomes by webhook. payments-api verifies each event, stores it once, and updates the charge. The handler is src/routes/webhooks.ts.

Verification

The PSP signs the raw request body with HMAC-SHA256 and sends the hex digest in the psp-signature header. We compute the same digest with WEBHOOK_SIGNING_SECRET and compare in constant time. A mismatch returns 401 signature_invalid and nothing is stored.

Processing

  1. Insert into webhook_events. The PSP event id is the primary key, so a duplicate delivery is ignored.

  2. For charge.settled, set the charge to settled with settled_at.

  3. If anything fails, store the event in webhook_dead_letters with the error, and still answer 200. The PSP retries non-2xx answers for 3 days, which would hide the problem; we prefer to replay ourselves.
