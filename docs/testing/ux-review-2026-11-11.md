# UX review, 2026-11-11 (core 4.13.0, development)

A first-time-user walkthrough of Doc Drift Sentinel on https://one-atlas-jzzf.atlassian.net, driven in a real logged-in Chrome (Razvan, site admin). Six personas, end to end. Screenshots are in [ux/](ux/). No app code was changed and nothing was deployed.

Severity: **Critical** blocks the flow or misleads about trust. **High** costs a judge or first-time user real confusion. **Medium** is friction or inconsistency. **Low** is polish. Effort: **S** under 1 hour, **M** half a day, **L** a day or more. Every fix below is UI Kit feasible unless it says otherwise.

## Persona 1: admin installing the app for the first time

**Steps.** Confluence home > Apps menu ([01](ux/01-global-apps-menu.jpg)): no Doc Drift entry. Settings cog > Confluence administration > scroll the sidebar > Settings > Apps > "Doc Drift Sentinel (Development)" ([02](ux/02-admin-apps-menu.jpg)). Read the page top to bottom ([04](ux/04-settings-detection.jpg), [05](ux/05-settings-spaces-escalation.jpg), [06](ux/06-settings-relay.jpg), [07](ux/07-settings-demo-mode.jpg)). Tried "Selected spaces only" with none picked and escalation 99, then Save ([08](ux/08-settings-validation.jpg)).

**What works.** One clear intro sentence, grouped cards, help text under every field, sentence case, numbers as digits. Validation is excellent: inline errors on every bad field plus "2 settings need a fix. Nothing was saved." The relay card shows Connected, last ping, last change and repositories seen. Demo mode explains exactly what PR #482 does.

## Persona 2: page owner anchoring a new page

**Steps.** DDSTEST > Create > Page. Wrote a runbook: intro with `PAY-142`, heading "Restart the worker", inline code `scripts/rollback.sh` and `config/workers/refunds.yaml`, a code block with `./scripts/refund-worker.sh restart` and `deploy/helm/refunds/values.yaml`, and the Bitbucket repo URL ([11](ux/11-new-page-draft.jpg)). Clicked the byline in the editor ([10](ux/10-draft-says-restricted.jpg)). Published, clicked "Doc Drift: Unanchored" ([12](ux/12-anchor-modal-suggestions.jpg)). Clicked Add anchor with empty fields ([14](ux/14-anchor-empty-error-layout-shift.jpg)), then path `/scripts/[bad` ([15](ux/15-anchor-bad-glob.jpg)), then `deploy/helm/refunds/**` critical, Add anchor, ticked 3 suggestions, Save and mark verified ([16](ux/16-anchor-saved-no-feedback-at-button.jpg), [17](ux/17-anchor-saved-top.jpg)). Closed, the byline still said Unanchored; reloaded ([18](ux/18-byline-verified-after-reload.jpg)).

**Clicks.** Minimum to anchor from suggestions: open byline (1) + tick each suggestion (1 each, 3 here) + Save (1) = **5 clicks**, plus a page reload to see the result. Manual anchor adds 4 to 5 more (type, type, critical, Add anchor).

**What works.** Suggestions are accurate: all 6 found (4 paths from inline code and code block, `PAY-142`, the repo). The repo was inferred from the URL. Glob error copy is specific ("Close every bracket, brace or parenthesis in the glob."). "Saving replaces the anchors and marks this page Verified." sets expectations. Success: "Saved 4 anchors. This page is Verified."

| Severity | Finding | Fix | Effort |
| --- | --- | --- | --- |
| High | On a draft (the natural moment to anchor) the modal says "Restricted pages can't be watched yet… Remove the restriction". The page is not restricted; the app just cannot read drafts. | In `resolvers/byline.ts`, check `status === 'draft'` before `appCannotRead` and return `draft: true` with "Publish this page first, then add anchors." | S |
| High | Badge does not change after save; the page keeps showing "Doc Drift: Unanchored" until reload. | backgroundScript refresh, or a "Reload page" button in the success message. | M |
| Medium | "Anchor" is never defined. A doc writer does not know whether to tick a file, a folder or the repo. | One-line definition under the Anchors heading (fix 10). | S |
| Medium | Suggestions are unticked by default and listed in body font; paths are not in mono. "payments-api (whole repo)" is offered with no warning although it flags the page on every merge. | Pre-tick paths found in code blocks; mono labels; move "whole repo" last with "(flags on every merge)". | S |
| Medium | Success message renders at the top of a scrolled modal, so after clicking Save at the bottom nothing visible changes ([16](ux/16-anchor-saved-no-feedback-at-button.jpg)); you have to scroll up to learn it worked. | Render the result next to the Save button, or scroll to top on success. | S |
| Medium | Two-step manual add: filling the form and pressing "Save and mark verified" without "Add anchor" is easy. (Not verified whether the typed anchor is kept or dropped.) | On Save, if the add form has a path, add it or show "Add or clear the anchor you typed." | S |
| Low | Empty Add anchor: the Repository field widens to fit its error and pushes Anchor path right ([14](ux/14-anchor-empty-error-layout-shift.jpg)). | Fixed column widths (`Inline` with `grow` off / `Box` widths). | S |
| Low | Anchors table: every row repeats "Critical anchor" beside a checkbox, and anchors sit in grey input-like boxes that look editable. | Column header "Critical", bare checkbox per row; plain `Code` for the anchor. | S |

## Persona 3: reviewer handling drift

**Steps.** DDSTEST page 2752731 (Possibly stale, PR #4 and PR #482): opened panel ([19](ux/19-review-panel-top.jpg)), scrolled ([21](ux/21-review-panel-duplicate-events.jpg), [20](ux/20-review-panel-bottom-actions.jpg)), opened Dismiss ([22](ux/22-dismiss-reason-form.jpg)), cancelled, Snooze 7 days ([23](ux/23-snoozed-feedback.jpg)), Mark verified ([24](ux/24-after-verify-view-jumps.jpg), [25](ux/25-after-verify-top.jpg)). Page 3047452 (Stale, 4 changes): opened ([26](ux/26-stale-review-card-width.jpg)), dismissed as false positive ([27](ux/27-dismissed-feedback.jpg)). PLAT Refunds API guide: read only ([30](ux/30-plat-refunds-review.jpg), [31](ux/31-plat-refunds-no-section.jpg)).

**What works.** The header line is exactly right: "PR #4 changed an anchor 5 hours ago (+1 change). Agents are told not to trust this page until someone reviews it." Event cards name the PR, who merged it, the PR title, the rename with an arrow, line counts, severity and the matched anchor. "Affected section" quotes the real passage with the token bolded. Dismiss requires a reason, the confirm button counts ("Dismiss 2 changes") and the help says what happens. "Snoozed for 7 days. The 2 open changes stay on the page until someone reviews them." is calm and specific. "Marked Verified. Agents can cite this page again." closes the loop. "No section on this page names the changed files. Read the whole page before you verify it." is an honest fallback.

| Severity | Finding | Fix | Effort |
| --- | --- | --- | --- |
| High | Each event dumps 25+ lines of raw `git diff`, including `diff --git`, `index a41f113..`, `similarity index 56%`. A doc owner who did not write the code scrolls past 50 lines of noise to reach the actions; the Refunds API guide shows 40 lines of a deleted file. | Summary first; diff behind a "Show diff" button (state toggle); drop git header lines; cap at 12 lines with "View PR #12 in Bitbucket". | M |
| High | Actions (Dismiss, Snooze, Mark verified) are only at the very end of a long scroll. | Repeat the action row under the header, or move it above "What changed". UI Kit modals cannot pin a footer from a byline modal, so duplicate it. | S |
| Medium | After Mark verified the view switches to the Anchors layout but keeps the scroll offset; the user sees the "Add an anchor" form and no confirmation ([24](ux/24-after-verify-view-jumps.jpg)). | Show the result where the click was, as Snooze does. | S |
| Medium | Feedback position is inconsistent: Snooze result at the bottom, Verify and Dismiss results at the top. | One rule: result directly above the action row. | S |
| Medium | After dismissing all changes the header says "Verified, 4 hours ago." with no name, implying a fresh verification ([27](ux/27-dismissed-feedback.jpg)). | "No open changes. Last verified by Dana 4 hours ago." | S |
| Medium | Event cards without a diff shrink to ~60% width while others are full width ([26](ux/26-stale-review-card-width.jpg)). | Give the card `Box` `xcss={{ width: '100%' }}`. | S |
| Medium | The reasons line is a dense run-on in body font: "scripts/rollback.sh renamed to scripts/rollback-v2.sh · Page mentions ROLLBACK_TIMEOUT and rollback.sh, removed in PR #4". Paths and identifiers are not mono. | Split into bullets; render identifiers with `Code`. | S |
| Low | After Snooze the Snooze button stays in its pressed state and can be clicked again. | Disable it and relabel "Snoozed until Nov 18". | S |
| Low | "Dismissed 2 times" under each anchor is useful but unexplained. | Tooltip: "Changes to this anchor were dismissed 2 times. Future changes score lower." | S |

## Persona 4: space lead on the dashboard

**Steps.** PLAT > Space apps > Drift dashboard ([29](ux/29-dashboard-top.jpg), [36](ux/36-dashboard-table.jpg)). Clicked a column header. Clicked "Refunds API guide". DDSTEST dashboard after my reviews ([35](ux/35-dashboard-empty-ddstest.jpg)).

**What works.** "Drift in PLAT" plus one line on agents. KPI tiles match the copy library (18 of 24, 75% of the space; 5 Possibly stale; 0 Stale; median "Under 3 hours"). Table states its ranking ("Ranked by severity, then state and open changes."), shows state word plus icon, severity, open changes, since and owner with avatar. Empty state copy is on brand: "No drift in DDSTEST this week. 5 of 6 pages anchored."

| Severity | Finding | Fix | Effort |
| --- | --- | --- | --- |
| High | It answers "what is drifting" but not "what do I do next": rows link to the page, then the lead must find and click the byline. | Per-row "Review" link that opens the panel (deep link param read by the byline), or a ModalDialog from the dashboard reusing the review component. | M |
| Medium | Columns are not sortable (clicking "Since" did nothing). | `DynamicTable` with `isSortable` and sort keys. | S |
| Medium | No list of unanchored pages, though "18 of 24" invites "which 6?". That is the coverage job. | Collapsible "6 pages not anchored" list under the KPI tiles. | S |
| Medium | Severity "High" uses the same amber chip as "Possibly stale", so every row is amber twice. On our own surfaces the brand says one beacon per view; inside Confluence it still reads as noise. | Severity as `Lozenge appearance="removed"` (High) / `"default"` (Medium), or plain text. | S |
| Low | "Since" wraps ("4 hours / ago"); "Open changes" header wraps. | Narrower Page column or "Opened" header; short times ("4h ago"). | S |
| Low | Page H1 is "Drift dashboard (Development)" then H2 "Drift in PLAT": two titles. | Drop the H2 or make it the only heading (the module title is set by Confluence). | S |
| Low | Empty state says "this week" but reflects open drift right now. | "No open drift in DDSTEST. 5 of 6 pages anchored." | S |
| Low | Owner backlog "6 open changes" next to a table counting pages; the unit switch is easy to misread. | "6 open changes on 5 pages". | S |

## Persona 5: knowledge worker in Rovo

**Steps.** On PLAT Refunds API guide: Ask Rovo > agent picker > Drift Reviewer ([32](ux/32-rovo-drift-reviewer-start.jpg)). Prompt 1: starter "Is this page still current?" ([33](ux/33-rovo-stale-answer.jpg)). Prompt 2: "Can I trust the page "Refund worker runbook (UX review)" in the DDSTEST space?" ([34](ux/34-rovo-verified-answer-ambiguous.jpg)).

**Prompt 1 (stale page), about 15 s.** "The state of this page is **Possibly stale**. Do not present steps from this page as current. The code it is anchored to changed by PR #12 on 2026-11-11, which removed `src/routes/refunds-v1.ts`." Trustworthy, concise, honest wording, mono path. Follow-up chip "What changed in PR #12?" is apt.

**Prompt 2 (fresh page), about 10 s.** "The state of this page is **Verified**. Safe to cite. It was last verified by Razvan Statescu on 2026-11-11." Correct for the runbook, but the page context chip still reads "Refunds API guide", and the answer says "this page".

| Severity | Finding | Fix | Effort |
| --- | --- | --- | --- |
| Critical | Answer 2 never names the page. With the Refunds API guide (Possibly stale) as Rovo's context, "The state of this page is Verified. Safe to cite." reads as the open page being safe: the opposite of the product promise. | Prompt and SKILL.md rule: always open with the page title as a link: "Refund worker runbook (UX review) is **Verified**…".
