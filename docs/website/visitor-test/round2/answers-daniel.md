# Answers: Daniel (Confluence platform lead, 600 engineers), round 2

## A. First screen only (written before opening anything else)

1. It watches the code and Jira work behind a Confluence page and, when they change, marks the page "Possibly stale" and tells AI agents not to rely on it. Quote: "flags the page and warns AI agents before they rely on it."
2. Teams with runbooks and docs in Confluence whose code lives in Bitbucket ("For Confluence Cloud, with Bitbucket and Jira"). Probably platform or engineering leads like me. Not obvious whether GitHub teams are covered.
3. "See how it works", not "Install for Confluence". I install nothing on a 600-person site before I know what it reads and writes.
4. How does it know `scripts/rollback.sh` is what the page is about: linked by hand, or guessed? "PR #482 changed scripts/rollback.sh on Nov 13. Review." is clear, but how noisy is this across thousands of pages? "warns AI agents": through what channel? Who gets notified?

## B. Whole page

5. At the 3 a.m. section, but the hero card had already shown the idea. The line that made it real for my problem: "The page's review date can't see a code change." That is exactly my complaint about verification apps. Then "It watches the code and Jira work behind each page, and flags the page when they change."
6. (1) Link: a page is tied to the files and Jira issues it names ("Doc Drift suggests the files and Jira issues a page names. You confirm."). (2) A PR merges or a linked issue changes, and a plain rule decides if it matters. (3) The page reads Possibly stale, the owner is told, and a person reviews and re-verifies it.
7. Agents are told not to trust the page: "Our Rovo agent and coding assistants check Doc Drift before they rely on a page. If it may be out of date, they say so, and why." No, an agent never edits a page: "Agents never edit pages. People do." and the FAQ "Only when a person clicks to fix one. The edit is a new page version under their name, so page history can undo it." Slight loose end: "Our agent drafts other edits; nothing changes until you accept." So AI drafts text, a human applies it. Fine, but I want that stated once, plainly.
8. Trust: "No AI decides what's stale", "Plain rules: same change, same result", "Respects permissions", "Built on Atlassian Forge ... No servers of ours in between", the "Real recording · demo site, Nov 13" labels, restricted pages stated as unsupported, the admin controls ("Watch selected spaces only", "Choose Strict, Balanced or Quiet"). Against: an unknown vendor ("Nano Soft, Bucharest"), "In preview. The install link will be posted here.", and the admin links ("See what it reads and stores") sit as small underlined text, with no list of scopes on the page. "No servers of ours in between" sits oddly next to a Bitbucket relay and an HMAC-signed trigger I'd want explained. Also, the "Real recording" video is one PR on one demo site: no numbers from a real team.
