Setup guide

Install Doc Drift, link your Confluence pages to the code and Jira work they describe, and let AI agents check a page before they rely on it. You can try the whole flow without Bitbucket by replaying a demo pull request.

Quick start

  1. Install Doc Drift on your Confluence site.
  2. Anchor a page: link it to the files or Jira issues it describes.
  3. Connect Bitbucket, or replay the demo pull request.
  4. Review the flagged page, then mark it verified.
  5. Connect your coding agent over MCP.

Before you start

  • Confluence Cloud, and a site admin to install the app. Confluence administrators change its settings.
  • Jira Cloud on the same site, if you want Jira issues as anchors or want to create Jira tasks. Optional.
  • A Bitbucket Cloud team workspace, if you want merged pull requests to flag pages. Forge apps can't be installed in personal workspaces. Optional: the demo replay works without it.
  • Rovo, Atlassian's AI, on the site, for the Drift Reviewer agent and Propose fix. Everything else works without it.

Doc Drift is two Forge apps: the main app in Confluence, and a relay, a small Bitbucket app that sends each merged pull request to it. Forge doesn't let one app span Bitbucket and Confluence, so the relay is separate.

Install the app

The install link is shared with Codegeist 2026 judges first and will be posted here. If you're a judge, use the link on the Devpost entry.

Install for Confluence

  1. Open the install link and pick your site. Only a site admin can install.
  2. Review the permissions and select Install. Confluence is required. Jira is optional, and you can connect it after install.
  3. Open any published page. A Doc Drift item appears in the byline, the line under the page title. This guide calls it the badge; once the page has anchors, it shows the page's state, such as Verified · Doc Drift.
  4. Click the badge and allow access when asked. The app and your agents act as you, so each person grants this once.

Connect Jira

Jira is optional. With it, a page can be anchored to a Jira issue or epic, and some changes to that issue flag the page (see When a page is flagged). You can also turn a flagged page into a Jira task.

To connect Jira after install, an admin opens Atlassian Administration, then:

Apps › Sites › your site › Connected apps › Doc Drift › View app details › Connections › Jira › Connect

Then they review the new permissions. To stop Jira changes flagging pages without disconnecting, turn off Flag pages when an anchored Jira issue changes in the app settings.

Connect Bitbucket

When a pull request merges into a repository's main branch, the relay sends Doc Drift its number, title, author, branches, changed files and diff. Each request is signed with a secret that only your site and the relay know.

  1. In Confluence, open Settings (the gear), then Doc Drift in the sidebar. Under Bitbucket relay, copy the Ingest URL and select Generate secret. Copy the secret now: it's shown only once.
  2. Install the Doc Drift Relay in your Bitbucket team workspace with its install link.
  3. In Bitbucket, open Workspace settings, then Doc Drift Relay under Forge apps. Paste the URL into Core ingest URL and the secret into Shared secret, then select Save.
  4. Select Send test ping. It should say Connected, and the Confluence settings page shows the time of the last test ping.

After the first merge, the settings page lists the repository under Repositories seen. For large pull requests the relay sends the first 500 files, and leaves out the diff above 300 files or cuts it at about 200 KB. Rotate secret stops the old secret at once, so update the relay right after.

Try the demo replay

The demo replays a seeded pull request through the same path the relay uses, so you need no Bitbucket. PR #482 in payments-api renames scripts/rollback.sh to scripts/rollback-v2.sh, and the variable ROLLBACK_TIMEOUT to ROLLBACK_TIMEOUT_SECS.

  1. Make a page that mentions scripts/rollback.sh, publish it, and anchor it to repository payments-api, path scripts/rollback.sh.
  2. In the app settings, under Get started, select Replay seeded PR #482.
  3. After a few seconds, reload the page. The badge reads Possibly stale · Doc Drift: what the page describes changed, so it may be out of date. Open it to see the change, the affected section and the rename quick fix.

To get the owner comment straight away, set Wait before commenting, in minutes to 0 in settings first.

Anchor pages

An anchor links a page to a file, folder or Jira issue it describes. When that changes, Doc Drift flags the page: it turns Possibly stale, and agents are told not to rely on it. To add anchors, click the badge; if the page has open changes, open its Anchors tab.

AnchorType to pickExample
FileFile path or glob, with a repository and a pathpayments-api, scripts/rollback.sh
Folder or globFile path or glob, with a pattern. ** matches everything below a folder, and a path ending in / watches the whole folderdeploy/helm/**
Jira issue or epicJira issue, with its keyPAY-142
Whole repositoryWhole repository, with a repository. It rarely flags a page: prefer pathspayments-api
  • Suggestions. Under Suggested from this page, Doc Drift lists the paths in code, Bitbucket links and Jira keys it finds on the page. Only checked suggestions are added when you save.
  • Critical anchor. Tick it for a file whose change should always get attention, such as the script a runbook runs. Critical anchors flag on smaller changes, and their changes count as High.
  • Save and mark verified saves the anchors and marks the page Verified. Changing anchors needs edit rights on the page.
  • Anchor this space. On a space's Drift dashboard, this suggests anchors for up to 25 unanchored pages at a time. It lists only pages with suggestions, and saves only on pages you can edit.

When a page is flagged

Fixed rules decide, not AI, so the same change always gives the same result. Doc Drift compares what a change touched with each page's anchors. These are the rules at the default setting, Balanced:

AnchorFlags the page when
FileThe file is renamed or removed. Edits flag it when they're bigger: about 6 changed lines (lines added plus lines removed).
Critical fileAny edit, unless it only touches comments or whitespace.
Folder or globOnly with page evidence (below). The size of a change alone isn't enough.
Critical folder or globA file in it is renamed or removed, or an edit has about 19 changed lines.
Whole repositoryOnly with page evidence, and not always then. It never flags on size.
Jira issue or epicIt moves to Done (any done status) or Won't Do, or is resolved as Won't Do; its fix versions, components, parent or description change; or it's deleted. Other status moves and summary edits don't flag it.

Page evidence makes any code match stronger: the page names something the change removed, such as ROLLBACK_TIMEOUT, or a code block on the page has a line the change removed. At Balanced, with page evidence, a small edit is enough for file, folder and glob anchors.

Strict and Quiet settings

Sensitivity in settings moves these lines for every page. Strict flags more pages; Quiet flags only strong matches.

AnchorStrictQuiet
FileAny editRenamed, removed, or about 50 changed lines
Critical fileAny editRenamed, removed, or about 3 changed lines
Folder or globA file in it renamed or removed, or about 60 changed linesOnly with page evidence
Critical folder or globRenamed, removed, or about 4 changed linesOnly with page evidence
Whole repositoryOnly with page evidenceOnly with page evidence
Jira issue or epicSame as BalancedOnly Done, Won't Do or deleted

An edit that only touches comments or whitespace counts for much less, so it rarely flags a page. Each dismissal also makes that anchor a little less sensitive.

Changes that never flag a page

  • Changes to files that match Ignore globs, one per line: by default tests, lock files, snapshots, dist folders and Markdown. So an anchor on a Markdown file never flags.
  • Merges into a branch other than main, while Only count merges into the main branch is on.
  • Any change, for pages in spaces that aren't watched. They keep their anchors.
  • Jira changes, while Jira is turned off in settings.

Renames and reverts

  • Renames. A file anchor still matches a renamed file by its old path, and the review panel offers to move the anchor to the new one.
  • Reverts. A pull request titled Revert "…" closes the open changes of the pull request it reverts. Other pages are checked as for any change, so a page already reviewed for that pull request can be flagged: the code it describes moved back.

Review a flagged page

Click the badge on a Possibly stale or Stale page. The Review tab lists each change under What changed: who made it, when, the files, and why it flagged this page. Affected section shows the parts of the page that name what changed.

Each change is High or Medium: High when the anchored file was renamed or removed, the anchor is Critical, or the match is strong. People who can edit the page also get Show diff and the full Jira values.

ActionWhat it does
Mark verifiedRecords that you checked the page against the changes, and closes them.
Quick fixWhen the page names a renamed file, its button, such as Replace in 2 places, swaps in the new path as you, with a version message naming the pull request. No AI. It also closes that change, and moves a file anchor that pointed at the old path.
Propose fix, under Proposed fixOpens Drift Reviewer in Rovo to draft new text, one block of the page at a time. Drafts appear in the panel, and the page doesn't change.
Accept draft, Accept fixSaves drafts as a new page version, as you, with a version message such as Doc Drift: accepted proposal for PR #482. Accept fix accepts every open draft, Accept all for this section one section's drafts, and Reject draft drops one. A change closes once its last draft is accepted.
Move anchor or Keep, under Renamed anchorsAfter a rename, moves the anchor to the new path or keeps it on the old one. The change stays open until someone reviews the page.
Snooze 7 daysPauses every open change for 7 days. They stay listed as Snoozed, and the page reads Possibly stale meanwhile, even if it was Stale. Agents are still warned, and the owner gets no comment about those changes.
DismissCloses every open change with a reason: Not relevant, Already updated or False positive. The page reads Verified, with you as the reviewer, and each dismissal makes that anchor a little less sensitive. With Not relevant, you can also stop watching a path for this page.
Create Jira task, under Track in JiraCreates a task as you, listing the changes and sections to re-read. The changes then show Tracked in and the key, such as PAY-201, and agents are told an update is tracked there. Closing the task doesn't verify the page.

Mark verified and Create Jira task need view rights on the page; the rest need edit rights (see Who can do what).

Page states

Once a page has anchors, its badge shows the state as a word. The cite policy is the same advice in a form agents can read.

StateMeansAgents are toldCite policy
VerifiedNothing has flagged the page since a person last verified it or saved its anchorsSafe to citecite
Possibly staleAn anchor changed after the last verification, so the page may be out of date. A first change always leads here, never straight to StaleDon't present its steps as current, with a caveat that names what changedcite_with_caveat
StalePossibly stale for 7 days (the Days before Possibly stale becomes Stale setting), or 3 or more open changes, or a further High change to a Critical anchorThe same, and how long it's been unrevieweddo_not_cite
UnanchoredNot linked to code or Jira yetDoc Drift can't tell if it's current: cite with carecite_with_caveat

A Verified page also shows that the watch is working. Its badge tooltip reads, for example, Verified on Nov 12. 1 anchor change since, none flagged. Watching 3 anchors.

Space dashboard

Each space has a Drift dashboard in its sidebar. It counts only the pages you can view.

  • Pages anchored, Possibly stale, Stale and Median time to verify, in tiles.
  • Pages with drift, ranked by severity, then state and open changes. Filter it with Show, and open a page from its title or Review.
  • Owner backlog: open changes by page owner.
  • Anchor this space, while pages are unanchored (see Anchor pages).

Connect coding agents

MCP is an open standard that lets AI tools use other apps. Doc Drift's MCP server has 3 read-only tools: check-page-freshness, find-docs-for-path and list-stale-pages. Agents sign in as a person and see only the pages that person can view.

  1. An admin turns on the tools. In Atlassian Administration: Apps › Sites › your site › Connected apps › Doc Drift › View app details › Tools. Turn on Expose tools to MCP-compatible apps: this one switch turns on all 3 tools for that site.
  2. Each person opens the app once in Confluence and allows access, if they haven't yet. Signing in to the MCP server doesn't grant this.
  3. Add the server. The URL is the same for every site: when you sign in, you pick a site where the tools are on. In Claude Code, run the command below, then /mcp in a session to sign in.
claude mcp add --transport http doc-drift https://mcp.atlassian.com/forge/12e968a1-a45d-4524-ba28-d47e2315db1a

Other MCP clients

We've tested Claude Code. Other clients that support remote MCP servers with sign-in should work with the same URL.

Cursor, not yet tested by us: put this in .cursor/mcp.json or ~/.cursor/mcp.json.

{ "mcpServers": { "doc-drift": { "url": "https://mcp.atlassian.com/forge/12e968a1-a45d-4524-ba28-d47e2315db1a" } } }

Tell the agent when to use it

Paste this into CLAUDE.md or AGENTS.md. The same text is in the app settings under For coding agents.

Before you rely on a Confluence page, call the `check-page-freshness` tool from the doc-drift MCP server with its page ID or URL. If the state is not `verified`, do not present its steps as current, and tell the user which page needs a review. When a page and the code disagree, trust the code.

Drift Reviewer in Rovo

Drift Reviewer is our agent in Rovo, Atlassian's AI. It says whether a page is safe to cite, explains what changed, and drafts fixes for a person to accept. Find it in Rovo Chat, or select Propose fix in the review panel to open it with the page.

  • Ask “Is this page still current?” or “What changed since this page was verified?”
  • Ask it to draft a fix. It saves one draft per block after Rovo asks you to confirm, and you accept drafts in the review panel. Drafting needs edit rights on the page.
  • Tell it you checked the page, and it marks the page Verified after Rovo asks you to confirm. It does this only when you say you checked.

AI runs only when someone chats with Drift Reviewer or asks for a drafted fix, and those chats use your site's Rovo credits. Detection never uses AI. Drift Reviewer never edits a page, and treats page and diff text as evidence, not instructions.

Other Rovo agents don't check pages on their own. An agent built in Rovo Studio can add Doc Drift's tools.

Troubleshooting

An agent tool says to grant access in Connected apps

The person signed in to the MCP server hasn't opened the app in Confluence yet. Open any page, click the Doc Drift badge and allow access, then retry. After an app upgrade that adds permissions, do this once more.

There's no badge on a page

Confluence shows app byline items only on published pages. Publish the page and reload it.

A page with view restrictions can't be anchored

Restricted pages can't be watched yet: the app can't read them, and their changes don't reach it. Agents are told to check those pages against the code before citing them.

A merge didn't flag the page
  • It's a change that never flags: a branch other than main, ignored files such as tests or Markdown, or a space that isn't watched (see Changes that never flag a page). For an unwatched space, the badge panel says This space isn't watched yet., with an Open settings link for administrators.
  • The change was too small for the anchor. At the default setting, edits to a file anchor need about 6 changed lines, and folder anchors need page evidence unless they're Critical. Anchor the exact file, tick Critical anchor, or try Strict (see When a page is flagged).
  • It hasn't arrived yet. In our tests, a merge flagged its page 11 to 19 seconds later; Jira changes can arrive up to about 3 minutes late.
The relay test ping fails

Check that the URL and secret match the ones in Confluence settings. If you rotated the secret, paste the new one. In a personal Bitbucket workspace the relay can't be installed: use a team workspace.

The badge didn't update after an action

Reload the page. The badge state is stored with the page and refreshes on the next load.

A restored page lost its anchors

Trashing a page removes its anchors and closes its open changes, so a restored page comes back Unanchored: add its anchors again. A moved page keeps its anchors and state in its new space.
