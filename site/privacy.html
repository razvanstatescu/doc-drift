In short

  • No servers of ours. Both apps run on Atlassian Forge and keep their data in Forge storage for your site. The Bitbucket relay talks only to the Confluence app.
  • No page bodies kept. Pages are read to match changes and find the affected sections. The app keeps anchors, states, change details and file paths, and a fix draft keeps the one block it replaces.
  • Diffs are deleted after 30 days. File lists and pull request titles stay, so the history still makes sense.
  • No AI in detection. Fixed rules flag pages. AI runs only in Rovo, when someone chats with Drift Reviewer or asks it to draft a fix.
  • Permission-aware. People and agents see only pages they can view. Diffs are shown only to people who can edit the page, and never through MCP.
  • Pages change only on a click. Page text changes only when a person applies a fix, as that person. On its own, the app writes only badge data and owner comments.
  • This website doesn't track you. It has no analytics and sets no cookies. GitHub Pages hosts it and logs visitors' IP addresses for security.

Who we are

Where data lives

Doc Drift is two Forge apps: the main app in Confluence, and a relay in Bitbucket. Forge runs both on Atlassian's cloud, and the apps send data to no service outside Atlassian.

  • App data is kept in Forge hosted storage (Forge SQL and the Key-Value Store). Atlassian encrypts it at rest, keeps each installation's data separate, and stores it in the same location as your Atlassian site, so it follows your data residency settings. Source: Forge storage overview.
  • The relay's only outbound address is the Confluence app's Forge web trigger (*.webtrigger.atlassian.app). Every request is signed with a secret generated on your site. The Confluence app keeps the secret in Forge's secret store and shows only a short fingerprint.
  • App logs record IDs, counts and outcomes, plus repository names, file paths, change reasons, badge tooltips and the lines of owner comments, which name pull request authors. They never contain page text. Nano Soft can read these logs for your site to fix problems, unless an admin turns off Logs access in the app's details in Atlassian Administration. Source: Access app logs.

The badge state is also written to a content property on each anchored page, so the badge loads with the page. It holds a title that leads with the state, such as Possibly stale · Doc Drift, and a tooltip.

When AI is used

Detection never uses AI. Fixed rules compare the files and identifiers a change touched with each page's anchors, so the same change always gives the same result.

AI is used only in Rovo, on your site: when someone chats with Drift Reviewer, or clicks Propose fix, which asks it for a draft. Drift Reviewer runs under Atlassian's terms for Rovo and uses your Rovo credits.

It receives the page's title and state, a summary of each change, and the page sections that mention the changes, up to 5, with long blocks cut at 2,500 characters. If the person asking can edit the page, it also gets up to 4,000 characters of each change's diff and the full text of changed Jira fields. The page context it reads is at most 15,000 bytes, and never a whole repository.

It can save drafts, but only a person can apply one to the page. The apps call no other AI service.

When a coding agent calls an MCP tool, the answer goes to that agent and its AI provider. The MCP tools never return diffs.

Who sees what

  • The review panel, Drift Reviewer and the MCP tools read pages as the signed-in person. A page that person can't view comes back as unknown, with no title.
  • Anyone who can view a page sees that it drifted and a summary: the change, its author, the file paths and why it matched. Raw diffs and full Jira field values are shown only to people who can edit the page, and never to MCP tools.
  • Owner comments are ordinary page comments, so anyone who can view the page can read them.
  • Pages with view restrictions aren't supported yet: the app doesn't watch them.
  • Settings are for Confluence administrators. The relay's settings are for Bitbucket workspace admins.
  • Coding agents connect through Atlassian's MCP gateway with OAuth, only after an admin turns the tools on for the site, and only as the person who signs in.

What the apps change

  • Page text changes only when a person accepts a fix or applies the rename quick fix. The edit is made as that person, with a version message naming the pull request, so page history can undo it.
  • Badge data: the content property behind the badge. The app writes it after checking the clicking person's rights, and on its own when a change arrives, a page turns Stale, a snooze ends, or a page is trashed or restored.
  • Comments: a footer comment on a flagged page that mentions the owner, and the pull request author when their account is on your site. There is at most 1 new comment per page in 24 hours, and later changes are added to it. Administrators can turn comments off.
  • Jira tasks are created only when a person uses Create Jira task, as that person.

Retention and deletion

  • Diff text is deleted 30 days after a change arrives, by a daily job.
  • Removing an anchor deletes it. When a page is trashed or deleted, its anchors and state are deleted, its open changes close, and its open drafts are rejected.
  • When the app is uninstalled, Atlassian keeps its Forge storage for 28 days, then deletes it. Within 21 days, Nano Soft can ask Atlassian to link it to a reinstall, with your consent. Source: data lifecycle for Forge-hosted storage.
  • When the apps delete data, Atlassian keeps a soft-deleted copy for its retention period, to recover from accidents, then destroys it. The apps can't read that copy.
  • Content properties, comments, page versions and Jira tasks the apps created belong to Confluence and Jira, and stay until you delete them there.

To have data for a person or a page removed before then, email hello@nano-soft.tech.
